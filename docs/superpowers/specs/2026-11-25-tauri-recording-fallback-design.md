# Rust + Tauri 录像兜底播放器设计

日期：2026-11-25

## 背景

当前项目是直接通过浏览器运行的本地 HTML/CSS/JavaScript 播放器，使用 hls.js 播放 HLS 直播。实测 Bloomberg TV+ 在原直连线路下出现清单超时和分片下载不足，接入 SD-WAN 后恢复，确认主要故障来自网络链路。纯网页无法读取 Windows 系统代理状态，也不适合作为长期、可靠的 8 小时录像管理器。

本设计将应用升级为 Rust + Tauri 桌面程序，复用现有界面与 hls.js 播放逻辑，由 Rust 管理原生能力和 FFmpeg 录像。目标是在直播持续无画面时自动播放本地最近录像，并在直播稳定恢复后自动切回。

## 目标

- 检测并展示 Windows 系统代理配置，不修改系统设置。
- 应用运行期间自动保存一份逻辑上的近 8 小时滚动录像。
- 录像独立从直播源拉流，不通过视频画面采集，不重复编码，也不保存第二份副本。
- 连续 15 秒无新视频帧且录像可用时，自动切换到录像。
- 优先播放最近录像，随后循环播放当前近 8 小时录像。
- 直播连续稳定约 30 秒后自动切回。
- 明确展示直播、录像、代理和存储状态，保留现有操作日志能力。

## 非目标

- 不承诺补齐源站中断期间未录制的内容。
- 不承诺直播与录像之间无黑场、无加载或时间戳完全连续的切换。
- 不实现退出应用后的后台录像；如需此能力，应另行设计 Windows 服务。
- 首版不解析或执行 PAC 脚本，不自动开启、关闭或修改系统代理。
- 不将单个 8 小时大文件作为存储格式，避免异常退出损坏整段录像。

## 技术选型

采用 **Rust + Tauri + 现有 Web 前端 + FFmpeg sidecar**。

Tauri 在 Windows 使用 WebView2，能够复用当前 `design.html`、`app.js`、`logger.js` 和本地 hls.js。Rust 原生层负责网页无权处理的系统代理、进程、文件和本地服务。FFmpeg 直接拉取直播源并以流复制方式录像，避免 MediaRecorder 的实时编码开销和浏览器存储限制。

GPUI 虽支持 Windows，但仍处于 pre-1.0，且需要重写现有界面并另行集成视频解码、音频同步和 GPU 帧渲染，因此不采用。Electron 可以复用前端，但不符合已确认的 Rust 技术方向。

## 总体架构

### Tauri / Rust 原生层

职责包括：

- 读取 Windows 当前用户的代理配置，区分关闭、手动代理和 PAC。
- 管理 FFmpeg 子进程的启动、正常运行、异常退出和有限重试。
- 管理固定录像目录、滚动清单、过期分片和异常残留。
- 提供只绑定 `127.0.0.1` 的只读录像服务，不向局域网开放。
- 监测录像清单更新、新分片增长、磁盘占用和录像可用时长。
- 通过 Tauri command 接收前端请求，通过 event 向前端发送状态，避免前端轮询文件系统。

### WebView 前端

保留当前频道、设置、日志、播放控制和 OBS 使用方式，新增：

- 系统代理、直播链路、录像状态和磁盘占用显示。
- 直播与录像播放状态机。
- 录像不可用、录像兜底、恢复验证和自动切回提示。
- 将 Rust 上报的录像与代理事件写入现有日志体系。

### FFmpeg 录像链路

FFmpeg 直接从当前频道 URL 拉流，采用流复制，不重新编码。录像输出为短分片和 M3U8 清单，目标分片时长约 10 秒，按约 2880 个分片保留近 8 小时。FFmpeg 自动删除正常滚动产生的过期分片；Rust 在启动时处理异常退出留下的无效或孤立文件。

录像与直播播放是两条独立链路：播放器卡顿不会直接停止录像，FFmpeg 也不依赖视频元素、`captureStream` 或页面可见性。按当前源约 3.8 Mbps 估算，8 小时录像约需 14 GB，实际占用以源码率为准。

### 本地录像服务

WebView 通过本地 HTTP 服务读取录像清单和分片。服务只读、只绑定环回地址，并使用随机端口和访问令牌降低其他本地网页误访问的可能性。令牌和频道敏感参数不写入日志。服务支持视频播放所需的分片读取与 Range 请求，不暴露任意文件路径。

## 代理检测与网络行为

Rust 定期检查 Windows 当前用户代理配置，并在应用恢复前台时重新读取。界面区分：

- 系统代理未启用：可能为直连，也可能为 SD-WAN 或其他透明代理。
- 手动代理已启用：展示代理地址，并将 HTTP(S) 代理显式传给 FFmpeg。
- PAC 已配置：展示 PAC 状态，首版不执行 PAC，FFmpeg 的实际连通性另行探测。

代理配置存在不代表代理可用，系统代理关闭也不代表没有 SD-WAN。界面必须分别展示“代理配置”和“实际直播/录像连通性”，不得根据注册表状态宣称线路正常。

应用不修改 Windows 代理设置。日志不得记录代理认证信息或频道 URL 查询参数。

## 录像生命周期

- 应用启动并选择频道后开始录像，最小化窗口不停止录像。
- 切换频道时停止旧频道录像，并为新频道建立独立的逻辑录像上下文。新频道开始写入前清理应用录像目录中的旧频道分片，防止不同频道混入同一清单，并确保全局只有一份录像。清理范围仅限应用管理的录像目录，不触碰用户其他文件。
- 同一时刻只保留当前频道的一份滚动录像。设计首版以单频道长期播放为主；若保留多频道历史，会在后续另行定义存储配额，不在本版隐式扩展。
- 退出应用时停止录像并尽量完成当前分片；下次启动检查并复用最近 8 小时内仍有效的录像。
- 清单和分片通过原子更新或等效方式降低半写文件风险；无法确认完整性的分片不进入可播放范围。

## 播放状态机

状态包括：`直播启动`、`直播正常`、`直播异常确认`、`录像兜底`、`直播恢复验证` 和 `无录像可用`。

### 直播观察

只有用户处于播放意图时才进行故障判定。暂停、手动停止、切换频道和主动重新拉流不计入连续无帧时长。综合以下信号：

- 视频 `waiting`、`playing` 和媒体错误事件。
- HLS 分片下载、入缓存和致命错误事件。
- `getVideoPlaybackQuality().totalVideoFrames` 或可用替代信号的视频帧进展。

### 进入录像

直播无新视频帧时进入异常确认并计时；连续达到 15 秒时：

- 若本地录像已具备可播放内容，切换到录像。
- 若没有可用录像，继续直播重连并显示“录像尚未就绪”，不伪装成录像播放。
- 暂停、频道切换和主动操作会重置故障计时，避免误触发。

### 录像播放顺序

进入录像后，从最近可播放位置前约 5–10 秒开始，以避开正在写入的末尾分片。播到录像末尾后，从当前近 8 小时录像的最早有效位置继续；直播一直未恢复时循环播放该录像窗口。

源站中断期间没有新分片，因此兜底内容是历史录像，不是对中断时段的补齐。

### 直播恢复与切回

录像兜底期间 FFmpeg 继续尝试拉流，不额外启动第二路直播下载。根据直播清单更新和录像新分片持续增长判断链路恢复。连续稳定约 30 秒后自动切回直播，切回前再次确认当前状态，避免频道切换或手动操作造成竞态。

切回后若再次持续无帧，仍按相同规则进入录像。稳定时长和状态检查共同减少直播与录像之间反复切换。切换过程允许短暂加载画面。

## 异常处理

- **启动即断网**：直播和录像均按退避策略重试，显示无可用录像。
- **FFmpeg 异常退出**：保留现有有效录像并记录退出状态，重试间隔依次为 1、2、4、8、15 秒，之后每 30 秒重试，直到频道切换或应用退出，不直接清空目录。
- **磁盘不足或目录不可写**：展示实际错误，停止无效写入并保留仍可读取的最新录像。
- **异常退出恢复**：启动时检查清单与分片，跳过损坏、不完整或无法确认完整性的内容。
- **录像播放失败**：记录错误并返回直播重连状态，不在两条播放路径之间高速切换。
- **配置变化**：频道变化会取消旧状态机和旧恢复验证，旧事件不得影响新频道。
- **依赖许可**：随包分发 FFmpeg 时保留对应许可证、版权和来源说明，不将其声明为 Apache-2.0。

## 验证设计

### 自动化验证

使用可控制的本地 HLS 测试源和虚拟时钟覆盖：

1. 正常直播时持续录像，播放与录像互不争用视频元素。
2. 分片延迟但未达到 15 秒时不切换，持续无帧达到阈值后进入录像。
3. 录像从最近内容开始，到末尾后按当前窗口循环。
4. 源站中断时不产生伪新内容，直播稳定恢复约 30 秒后自动切回。
5. 暂停、切换频道和手动重新拉流不会误触发或受到旧事件影响。
6. 过期分片滚动清理，不生成第二份录像，实际录像时长接近 8 小时。
7. 无录像、磁盘不可写、FFmpeg 异常退出、损坏分片和应用重启均有明确行为。
8. 代理关闭、手动代理、PAC 和配置变化显示正确，实际连通性与配置状态不混用。

### 端到端验证

在 Windows 发行包上使用真实 Bloomberg TV+ 源：

- 正常播放并确认录像增长，中断网络后进入录像，恢复后自动切回。
- 分别验证 SD-WAN、系统手动代理和直连状态，界面不将配置状态误判为连通性。
- 检查 OBS 能持续采集直播或录像画面及正确音频。
- 检查重启后的录像复用、磁盘占用、日志脱敏和 FFmpeg 许可文件。

## 实施边界

首版聚焦 Windows 单频道长期播放、运行期间录像和自动兜底。现有纯网页版本可继续保留作为轻量使用方式，但代理检测、原生录像和自动兜底只在 Tauri 桌面版提供。具体依赖版本、FFmpeg 参数、Tauri 权限配置和项目目录调整在实施计划中确定，并通过实际构建与端到端测试验证。
