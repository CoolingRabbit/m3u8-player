# m3u8-player

一个面向长期播放和 OBS 浏览器画面采集的本地 M3U8/HLS 播放器。基于原生 HTML、CSS、JavaScript 和本地打包的 hls.js，无需安装 Node.js，也不依赖在线 CDN。

当前版本：**v1.1.0**

## 主要功能

- 多频道添加、编辑、删除、搜索和切换。
- 自动从 M3U8 地址提取并显示域名标签。
- 频道、界面名称和播放设置保存在浏览器本地。
- 播放、暂停、音量、静音、全屏和播放区快速重新拉流。
- 实测视频分辨率、帧率、分片码率、直播延迟、可用缓存和网络趋势。
- 自动或手动设置播放延迟和目标缓存。
- 每日定时或分钟倒计时重新拉流，两种方式互斥，允许全部关闭。
- 全屏播放时，空闲 3 秒后自动隐藏控制栏和鼠标，活动后恢复。
- 网络异常自动重试，恢复网络后重新连接。
- 桌面端和移动端自适应布局。

## 下载与运行

### 使用发行包

1. 下载 [GitHub Releases](https://github.com/CoolingRabbit/m3u8-player/releases) 中最新版本的 ZIP。
2. 解压到本地目录。
3. 使用 Edge 或 Chrome 打开解压目录中的 `index.html`。
4. 首次播放默认静音，点击音量按钮取消静音。

hls.js 已包含在发行包内，播放库不需要联网下载，但直播源本身必须可访问。

### 从源码运行

仓库中的页面入口是 `design.html`，可以直接使用浏览器打开。

也可以在当前目录启动一个本地静态服务，获得更一致的浏览器存储和访问行为：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

然后访问：

```text
http://127.0.0.1:8765/design.html
```

主要支持最新版 Edge 和 Chrome。Safari 可使用原生 HLS 播放路径，但目前未完成同等程度的验证。

## 使用说明

### 频道管理

- 点击“添加新频道”，输入频道名称和 HTTP(S) M3U8 地址。
- 点击频道卡片即可切换。
- “编辑当前频道”和“删除当前频道”用于管理当前选中的频道。
- 搜索框同时匹配频道名称和域名。
- 点击页面左上角的 `m3u8-player` 可自定义界面名称，按 Enter 或移开焦点保存。

默认频道为 Bloomberg TV+：

```text
https://liveprodusphoenixeast.akamaized.net/USPhx-HD/Channel-TX-USPhx-AWS-virginia-1/Source-USPhx-16k-1-s6lk2-BP-07-02-81ykIWnsMsg_live.m3u8
```

### 播放控制

| 操作 | 效果 |
| --- | --- |
| 单击视频画面 | 不暂停，避免 OBS 操作时误触 |
| 双击视频画面 | 进入或退出全屏 |
| `空格` | 播放或暂停 |
| `F` | 进入或退出全屏 |
| `M` | 静音或取消静音 |
| 全屏时无操作 3 秒 | 隐藏控制栏和鼠标 |
| 全屏时移动鼠标、触摸或按键 | 恢复控制栏 |
| 播放区刷新图标 | 立即重新拉流 |

输入框和按钮获得焦点时，键盘快捷键不会覆盖正常编辑行为。

### 延迟与缓存

“智能播放”开启时，播放器会结合以下信息选择推荐参数：

- 服务端实际提供的直播窗口。
- 分片时长。
- 前一次播放中的卡顿情况。
- 当前可缓冲的直播内容。

“智能播放”关闭时，可手动设置：

- 播放延迟：5–120 秒。
- 目标缓存：20–300 秒。

这些值是目标上限，不是保证值。直播源没有保留足够历史分片时，浏览器无法创造额外缓存。例如 Bloomberg TV+ 当前通常只提供约 10 秒的直播窗口，因此无法真正实现 60 秒延迟或 180 秒缓存。

### 自动重新拉流

两种方式互斥，开启一种会自动关闭另一种：

- **每日定时重新拉流**：默认开启，默认时间为每天 04:00。
- **倒计时重新拉流**：默认关闭，间隔可设置为 1–1440 分钟，默认 60 分钟。

任意重新拉流都会重新开始倒计时，避免连续重复触发。两类任务都需要保持播放器页面打开，页面重新可见时会再次检查任务。

### 参数含义

- **视频分辨率**：读取视频元数据。
- **视频帧率**：优先根据解码帧计数计算，无法采样时才使用清单标称值。
- **当前码率**：根据最近约 10 秒的分片下载量计算，单位 Mbps；它反映实际下载吞吐量，不等同于编码器固定码率。
- **播放延迟**：当前播放位置距离直播边缘的时间。
- **可用缓存**：当前播放位置之后已经缓冲的可播放时长。
- **卡顿与丢帧**：分别来自播放等待事件和浏览器解码统计。

## OBS 采集建议

- 浏览器缩放保持 100%，OBS 画布和输出尽量与源匹配，例如 1080p、60 FPS。
- 不要最小化播放窗口，避免浏览器后台降频；可关闭 Edge 的标签页休眠和效率模式。
- OBS 转播需要取消浏览器静音，并确认采集到正确的浏览器音频输出。
- 使用独立浏览器窗口或配置文件，减少通知、弹窗和其他桌面内容被采集的风险。
- 如果丢帧偏高，检查浏览器硬件加速、GPU 驱动及 Edge 视频增强设置。
- 重新拉流会出现短暂的黑屏或加载画面，OBS 观众也会看到。每日任务建议安排在非播出时段。
- 当前版本不是无缝双播放器切换。如果需要完全无感重拉，可后续增加双视频预加载与切换。
- 当前版本已有 HLS 错误重试，但如果需要处理“画面冻结但没有致命错误”的情况，可后续增加连续无画面进展时自动重拉的看门狗。

## 限制与注意事项

- M3U8 清单及其分片必须允许浏览器跨域访问（CORS）。需要自定义 Cookie 或请求头的源可能无法直接播放。
- 播放器不会代理、转码或降低直播源清晰度。单码率源在弱网下不能自动切换到更低清晰度。
- 浏览器自动播放策略可能导致首次播放需要手动点击，默认静音有助于自动开始播放。
- 每日和倒计时任务不是系统级计划任务，关闭页面后不会继续执行。
- 长时间采集时应同时管理操作系统睡眠、屏幕关闭和浏览器后台策略。

## 项目结构

```text
m3u8-player/
├── design.html                 # 页面、样式和播放器布局
├── app.js                      # 播放、统计、频道和任务逻辑
├── build-release.py           # ZIP 发行包构建脚本
├── VERSION                     # 语义化版本号
├── vendor/
│   ├── hls.min.js              # hls.js 1.7.4
│   └── hls.LICENSE.txt         # hls.js 许可证
└── .github/workflows/
    └── release.yml             # 标签触发的自动发布流程
```

发行包构建时会将 `design.html` 重命名为 `index.html`。

## 构建发行包

只依赖 Python 标准库：

```bash
python build-release.py
```

生成文件位于 `dist/`，ZIP 会执行完整性检查。`dist/` 已被 Git 忽略，不会提交构建产物。

## GitHub 自动发布

1. 更新 `VERSION`，版本号遵循语义化版本格式。
2. 提交并推送 `main`。
3. 创建并推送相同版本的 `v*` 标签。
4. GitHub Actions 使用同一个 `build-release.py` 构建 ZIP，并创建 Release、上传资产。

## 数据与隐私

- 频道和设置仅保存在当前浏览器的 localStorage 中。
- 项目没有自建后端，不会将频道信息发送到开发者服务器。
- 浏览器会直接向直播源及其 CDN 发起请求，相关网络日志由对应服务提供方处理。
